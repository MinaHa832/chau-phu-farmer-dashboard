# 역할, 공급 모형, 고지 흐름 (2026-11-28)

기존 18개 RMU 및 54개 시범농가의 ID·등록 항목·기존 요청·급수·절수 기록을 유지한다. 첨부 `1126 소원 안.zip`은 정적 참조로 비교했다. 파일 URL은 브라우저 정책에 의해 차단되어 첨부본 자체를 실행했다고 주장하지 않는다. ZIP의 로컬 저장·역할 선택 코드를 복사해 인증이나 공유 서버를 대체하지 않았다.

## 역할과 경로

| 화면 | 서버 역할 | 범위와 주요 권한 |
|---|---|---|
| 농민 | farmer | 배정 농가 한 곳. 기존 등록 화면, 취수/저장수 확인, 관개 일정, 요청·신고, 고지 선택·확인 |
| 현장 협동조합 운영자 | cooperative | 배정 RMU. 요청 접수·조정, 공급 보정 자료 등록, 앱/종이 고지 발행·전달 기록. 실제 급수 완료량 입력 불가 |
| 펌프 운영자 | operator | 배정 RMU. 급수 요청 처리와 실제 급수량, 작기 비교 자료 입력 |
| 플랫폼 운영자 | platform | 전체 계획·계정·자료 관리, 공유 계획 게시. 신고 원문과 독립 검증 권한 없음 |
| 제3자 현장관리자 | manager | 전체 결과 열람, 신고 처리·절수 근거·현장 보정 모형의 독립 검증. 계정 승인·계획 게시·실제 급수 수정 불가 |

첨부본의 농민 시작 경로(새 취수 / 저장수 / 부족·급수 변경)를 복원했다. 기존 `actor=case|settlement`는 cooperative, `pump`는 operator, `review|formula`는 platform, `audit|thirdparty`는 manager로 연결한다. 예: `?role=operator&actor=audit`.

세 언어 ko/vi/en에서 신규 화면과 역할을 제공하고, 기존 기상·수자원·농가·급수·절수 화면의 번역 체계를 유지·보완한다. 농민이 직접 쓴 메모·신고 원문은 자동 번역하거나 변경하지 않는다.

## 수요와 공급

기존 수요 산식은 `ETc=ET0×Kc`, `max(ETc−유효강우,0)×ha×10/(Ea×Ec)`다. 유효강우는 기존 월 단위 USDA-SCS 산식을 사용하고 일별 강우 비율로 배분한다. 단기 Open-Meteo 입력, 내장 과거 기후, 예보 이후 월별 계획 기후를 구분한다. 품종/작물 규칙이나 기후가 없을 때 수요를 임의로 0으로 만들지 않는다. 기존 AWD 시범 건조기간도 유지한다.

새 공급 모형은 `Q=a×max(H−h0,0)^b`를 현장 수위·유량 쌍에 적합시킨다. 3개 서로 다른 수위/0.05m 범위는 프로그램 입력 최소조건이며 현장 검증 표준이나 충분한 표본 수라는 뜻이 아니다. h0는 현장 자료에 따라 입력한다. 현장에서는 같은 지점·기준면·시간의 수위와 유량을 다양한 수위에서 반복 측정해야 한다. 유량은 단면별 면적×유속의 합, 유량계, ADCP 등으로 측정하고 계측 기록·관측소 대응 근거를 보존한다.

배분에 쓰는 계획량:

`min[Q×3600×(1−여유율)×수원 몫, RMU 펌프 한도, 공유 수원 한도×몫] × 주간 가동시간 × (1−손실률)`

여유율은 입력 계획 여유와 적합 상대 RMSE 중 큰 값을 반영한다. 이 범위는 통계적 신뢰구간이 아니다. 공통 수원 식별자로 묶은 몫 합계는 100% 이하이며 같은 관측소와 수원 한도를 사용한다. 물리적 수원 ID·할당 비율·실제 펌프 능력의 현장 확인은 여전히 필요하다.

- 다른 관측소, 빈 값, 오래되거나 미래인 관측, 보정 범위 밖 수위, 역류/배수위 영향은 계산을 보류한다.
- 실제 공유 계획은 독립 검증된 모형을 요구한다. 편집 시 승인은 취소된다. 입력자 자신의 검증은 금지한다.
- 공개 시연의 모형은 서버에서도 강제로 가상으로 표시하며 실제 검증 승인으로 전환할 수 없다.
- MRC 본류 수위만으로 RMU 실측 유량이나 실제 공급 가능량이 확인되는 것은 아니다. 수위 연동 + 합성 곡선은 **가상 공급 시나리오**다.
- 미래 주차는 최신 수위를 고정한 가정이다. 미래 수위 예측이나 수리 운영 명령이 아니다.
- 기존 계량기·단면/유속·검증 유량·기관 계획량 입력과 백업 자료를 보존한다.
- 기존 임의 0.75–1.25 수위 배율 버튼은 보정 모형 화면으로 안내한다.

산출된 공급 초안은 기존 최소 비례 배분 및 위험45%/대기30%/형평15%/효율10% 계산으로 연결된다. 플랫폼 운영자가 계획을 게시해야 다른 기기에 반영된다. 부분 범위의 사용자 화면은 전체 배분을 재계산하지 않고 서버의 게시 계획을 받는다.

참고: [USGS 측정 개요](https://www.usgs.gov/mission-areas/water-resources/science/streamgaging-basics), [USGS 배수위·동적 수위-유량 관계](https://pubs.usgs.gov/publication/sir20245129/full).

## 앱/종이 고지

농민은 수신 방법을 app 또는 paper로 저장한다. 협동조합은 담당 RMU의 환경을 대신 설정할 수 있다. 고지는 서버의 게시 계획에서 해당 농가·주차·배분량을 가져오며, 브라우저가 임의로 보낸 배분량은 사용하지 않는다. 앱 고지는 앱 내 게시이고 이메일/SMS/푸시가 아니다. 종이는 인쇄용 화면을 제공하고 담당자가 출력·전달한 뒤 메모를 남긴다. 전달 기록과 농가의 수신 확인을 구분한다. 발행 당시 계획의 스냅샷이며 변경 계획은 새 고지가 필요하다. 요금 청구·자동 우편 발송은 구현 범위가 아니다.

## 공유 서버와 배포

`202611270001_roles_flow_notices.sql`은 기존 데이터를 삭제하지 않고 역할 제약과 RPC를 확장한다. 기존 승인된 실제 관리자만 platform으로 유지 승계하고, 공개 시연 manager는 독립 검증 역할로 유지한다. demo에 cooperative 18명, platform 1명을 추가해 총92개 가상 인격을 제공한다. 실제 Auth 사용자나 비밀번호는 생성하지 않는다. 기존 실제 이메일 인증 설정을 약화하지 않는다.

새 UI 배포 전에 마이그레이션을 적용한다. 기존 Supabase URL 및 Vercel 환경을 사용한다. RLS와 원시 테이블 권한 차단, 서버 유도 역할/범위, 낙관적 버전 검사, 감사 이력, 실제/가상 공간 분리를 유지한다.

검증: PostgreSQL 기반 역할/범위/고지/검증 권한 검사, HTTP 세션·요청 전달 검사, 수위 곡선·단위·자료 신선도·공동 수원 한도 검사, 기존 수요의 강우 차감·단위·누락·AWD 회귀 검사. 브라우저에서 실제 새 화면의 가상 곡선→공급 초안→계획 게시→종이 고지→전달 기록을 확인한다. 원격 MRC·기상 응답과 관측 시각은 `자료·물 계산 확인`에서 별도로 검사한다.
